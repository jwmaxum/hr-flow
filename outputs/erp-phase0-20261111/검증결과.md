# Excel 양식 검증 결과

2026년 11월 11일. 대상은 회사별 기초재고 및 거래별 입출고 양식 2종이다.

| 항목 | 결과 |
| --- | --- |
| 파일 생성 | XLSX 2개 내보내기와 재열기 성공. 파일 구조 검사 통과. |
| 실제 입력 시트 | 두 파일 모두 200행이 비어 있다. 예시·Mockup을 실제 입력란에 넣지 않았다. |
| 입력 영역 | 기초재고 A:P, 거래 A:AA에 수식이 없다. 참고 계산은 별도 열에 있다. |
| 계산 및 입력 변화 | 21개 검증 항목 통과. 품목·가격 입력, 단가/장부금액 방식, 공란/0/음수, 창고 누락, VAT·외화, 중복 거래행, 거래처 수동 검토, 기준일 경계를 포함한다. |
| 계산 오류 | 내보내기 전 계산 검사와 저장 파일 재열기에서 Excel 오류값 0건. |
| Mockup 보존 | 106개 품목의 원본 값과 공란을 보존했다. 입력 시트 수식이 Mockup을 참조하지 않는다. |
| Mockup 대사 | 106행 수량·금액·마진 대사와 10개 열 합계 차이 0. 창고 공란 106건, 기말수량 공란 49건, 음수 수량 3건을 재확인했다. |
| 식별값 | 예시 품목코드 `0001`을 저장 파일에서 텍스트로 재확인했다. |
| 입력 편의 | 표 필터, D10 고정 창, 기초재고 4개·거래 6개 유효성 검사 범위를 저장 파일에서 확인했다. |
| 보안 구성 | 매크로·외부 연결·삽입 이미지 없음. 참고 시트와 계산값을 DB 입력에서 제외하도록 명세했다. |
| 화면 검토 | 6개 시트와 주요 입력·계산 영역을 렌더링하여 제목·표·숫자·안내문 가독성을 확인했다. |
| 문서 일치 | 개발계획서와 상세 명세에 회사별 품목·단가 독립, Mockup 제외, 회사별 DB 반영 규약을 반영했다. |

계산 검증은 Artifact Tool 엔진에서 수행했고, 저장 파일은 별도 판독기로 확인했다. Microsoft Excel 앱의 직접 실행 검증은 수행하지 않았다.

서비스 코드를 변경하지 않았으므로 애플리케이션 빌드·TypeScript·린트·서비스 테스트는 이번 작업에 적용하지 않았다. 운영 DB 반영·배포·회사 간 접근 제어의 실행 검증은 업로드 기능 구현 후 수행해야 한다. 기존 사용자 변경 파일 `gemini.md`는 수정하지 않았다.

다음 개발은 회사별 ERP 기준정보와 업로드 미리보기·확정 API다. 동일 코드에 서로 다른 이름·가격을 사용하는 회사 2개로 DB 격리와 중복 반영 방지를 검증한다.
