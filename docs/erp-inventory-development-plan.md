# HR Flow 재고관리 ERP 개발계획서

2026년 11월 12일 · 4단계 거래서류 PDF·등록 인감 재사용 구현 반영

회사 사용자는 HR Flow에 로그인한 뒤 대시보드의 **HR Flow 아이콘 오른쪽에 있는 ERP 버튼**으로 재고 업무에 들어간다. 회사별 품목·거래처를 관리하고, Excel 업로드 또는 화면 입력으로 입출고를 확정한다. 품목별 입출고 총괄과 상세 원장은 같은 확정 자료에서 계산한다. 영문 Proforma Invoice, 한글 Invoice, 거래명세표는 동일한 품목·거래처 정보를 활용해 발행하며, 발행 시 회사에 등록된 법인 인감 이미지를 재사용한다.

**입력 데이터 기준**. 제공 양식의 106개 품목과 수량·금액은 Mockup이다. 각 회사는 자신의 품목명·매입/판매 단가·재고·거래처를 입력한다. 동일한 품목코드를 쓰더라도 회사별로 독립된 자료이며, 지정 Excel 양식 업로드 후 미리보기와 확정을 거쳐 로그인한 회사의 DB에만 반영한다. Mockup은 모든 회사에 공통 초기 데이터로 등록하지 않는다.

입출고 총괄 Mockup을 조사 목적으로 읽어 대사한 결과, 106개 품목 모두 기초수량＋입고수량－출고수량이 기말수량과 일치했고, 기초금액＋입고금액－출고원가가 기말금액과 일치했다. 매출 공급가액에서 출고원가를 뺀 값도 품목별 마진과 일치했으며, K~T열의 상세 합계가 마지막 행과 일치했다. **106행 모두 창고명이 비어 있고, 3행은 기말수량이 음수**다. 이 값은 창고 매핑과 음수 오류 검증 사례로 사용한다. 현재 자료에 대한 실사·장부 정정은 개발 착수 조건이 아니다.

이 `.xls`는 실제 BIFF8 파일이고 엄격한 판독에서 OLE 구조 오류가 발생했다. 운영 업로드는 **입력 영역이 값으로 구성된 표준 `.xlsx`**를 기본으로 한다. Mockup은 조사용 복구 판독으로 106행과 10개 합계 열을 대조했다. 실제 회사의 과거 파일을 변환해야 하는 경우 정상 재추출본과 대조한다. 반복적으로 받는 정상 `.xls`의 직접 지원 여부는 별도 검증 가능한 파서와 샘플을 확보하여 결정한다.

## 2. 업무 흐름과 권한

1. 활성 회사 사용자에게 기존 로그인 세션을 유지한 채 `/erp`로 이동하는 버튼을 제공한다. ERP 첫 화면은 **재고현황 · 입출고 · Excel 업로드 · 거래처 · 거래서류**를 제공한다. 품목 총괄에서 품목을 선택하면 기간 내 입출고 일자, 거래처, 수량, 단가, 원가 및 연결 문서를 확인한다.
2. 권한 초안은 회사 관리자에게 품목·거래처 관리와 담당자 지정을 허용하고, 지정된 ERP 담당자에게 초안 입력·업로드를 허용한다. 확정·취소·인감 포함 발행은 권한을 별도로 설정한다. 조회 전용 담당자에게는 필요한 재고 화면만 허용하고, 매입원가·마진과 인감 포함 PDF는 별도 권한으로 제어한다. 회사별 ERP 자료 접근 권한은 플랫폼 운영자에게 자동으로 부여하지 않는다.
3. 문서나 입출고를 처음 저장할 때 신규 거래처 정보를 함께 입력하면 회사 거래처 목록에 자동 등록한다. 다음 거래에서는 검색·선택하여 주소와 연락처 등을 채운다. 회사 내에서 사업자등록번호를 우선 대조하고, 해외 거래처는 국가와 등록번호를 함께 대조한다. 등록번호가 없거나 유사 이름만 일치하면 선택 후보를 제시한다. 기존 거래처 정보가 다르면 문서 한 건에만 적용하거나 마스터를 갱신하도록 구분한다.
4. 회사·품목·거래처·파일 권한은 서버가 Firebase 인증, 활성 상태, 현재 회사 소속과 업무 권한을 매 요청 확인해 결정한다. 회사 전환·권한 회수 후 화면 데이터도 다시 불러온다. URL을 직접 입력하거나 다른 회사의 ID를 전달하는 경우에도 같은 검사를 적용한다.
5. 품목코드는 회사 안에서 식별한다. 업로드한 단가는 해당 회사의 해당 거래에 보존하고, 다른 회사의 가격이나 과거 거래를 변경하지 않는다. 기존 품목의 기본단가 변경은 명시적인 선택과 변경 이력으로 관리한다.

## 3. Excel 입력과 재고 계산

### 입력 파일 구분

| 업로드 유형 | 주요 필드 | 반영 방식 |
| --- | --- | --- |
| 품목별 총괄 이관 | 원본 기간·기준일, 품목코드·품목명·규격·단위·창고, 기초/입고/출고/기말 수량·금액, 매출액·마진 | 과거 집계는 조회와 대사용으로 보관한다. 재고를 시작할 기준일의 기말수량과 기말금액을 관리자 검토 후 한 번만 기초재고로 반영한다. 동일 기간의 상세 원장이 있다면 기초재고와 중복되지 않는 시점을 선택한다. |
| 회사별 기초재고 표준 양식 | 회사별 품목·창고·기준일·기초수량, 단가 또는 장부금액, 통화 | 회사가 빈 양식에 입력한다. 단가 방식은 수량×단가로 계산하고 금액 방식은 장부금액을 보존한다. 제공 Mockup의 품목 수와 값은 강제하지 않는다. |
| 거래별 입출고 표준 양식 | 거래일, 구분, 거래 문서번호, 행번호, 품목코드, 창고, 수량, 단위, 단가, 통화, 세금 포함 여부, 거래처 식별값, 비고 | 입고는 수량과 매입단가를 저장한다. 출고는 판매단가와 판매금액을 기록하고 출고원가는 재고 평가 기준으로 계산한다. 거래일·거래처별 상세 조회는 이 유형과 화면에서 확정한 거래를 사용한다. |

총괄표의 입고금액을 입고수량으로 나누면 기간 평균 입고단가를 표시할 수 있다. 개별 매입단가나 개별 출고 이력은 거래일과 거래처가 있는 원본에서 받아야 한다. 창고가 비어 있는 경우 미지정으로 보여주고, 반영 전에 회사의 기본 창고 또는 매핑을 선택한다. 과거 음수 재고는 대사 화면에 표시하고, 기초재고 확정 시에는 수정 근거와 정상 수량을 확인한다.

업로드는 **형식 확인 → 열 매핑 → 미리보기 → 오류 수정 → 확정** 순서로 진행한다. 미리보기에 시트명·원본 행·오류 항목, 신규/기존 품목·거래처 후보, 집계 차이, 확정 시 수량과 금액 변화를 보여준다. 소수점·천 단위 쉼표·날짜·선행 0이 있는 품목코드의 변환 규칙을 명시한다. 실제 입력 범위는 값만 허용하고 합계는 서버에서 재계산한다. 원본과 검증 결과는 비공개로 저장하며, 업로드 단계에서 재고 변동을 만들지 않는다.

### 재고 원장과 잔액

- 품목과 창고별로 기초수량·기초금액, 입고수량·입고금액, 출고수량·출고원가, 기말수량·기말금액을 관리한다. **잔량은 기말수량, 잔액은 기말 재고금액**으로 표시한다. 공급가액(매출액)과 품목별 마진은 재고금액과 별도 열에 표시한다. 기간 시작 직전의 재고를 기초로 사용하고, 기간 종료일의 잔액을 표시한다.
- 1차 원가 방식은 **이동평균법 검토안**으로 두고 기존 장부와 대사한 뒤 확정한다. 예를 들어 기초 10개·10,000원과 입고 10개·12,000원을 합하면 평균원가는 1,100원이다. 4개를 1,600원씩 출고하면 출고원가 4,400원, 매출 공급가액 6,400원, 잔량 16개, 잔액 17,600원, 마진 2,000원이다. 금액은 통화 정밀도와 고정된 반올림 규칙으로 처리한다.
- 재고는 입고·출고·반품·조정을 확정할 때만 변한다. 출고는 확정 시 재고를 다시 검사하고, 초과 출고는 거절한다. 취소·정정은 원거래를 참조하는 역거래나 조정으로 기록한다. 소급 거래는 마감 여부와 이후 원가 재계산 정책을 확인한 뒤 반영한다.
- 확정 요청은 회사와 원거래의 식별자로 중복을 막는다. 파일 해시로 같은 업로드를 식별하고, 거래번호와 행번호로 서식이 바뀐 재업로드를 대조한다. 같은 수량·단가의 서로 다른 거래는 각각 보존한다. 서버 트랜잭션은 처리 기록과 현재고를 읽고, 확정 원장·현재고·확정 상태를 함께 기록한다. 파일이 여러 거래로 나뉘면 반영된 거래와 실패한 거래를 표시하고 실패 건만 재개한다. PDF 작업은 트랜잭션이 끝난 뒤 처리한다. [Firestore 트랜잭션](https://firebase.google.com/docs/firestore/manage-data/transactions) · [동시 수정과 격리](https://firebase.google.com/docs/firestore/transaction-data-contention)

## 4. 문서 발행 설계

| 문서 | 필드와 동작 |
| --- | --- |
| 영문 Proforma Invoice | 문서번호, 발행일·유효기간, Seller·Buyer, 품목 영문명·규격·수량·단위·단가·통화, 소계·세금·총계, 결제 및 납기·배송 조건. 해외 거래에 필요한 무역 조건과 은행 정보는 0단계에서 필수 여부를 결정한다. 출고 전 견적 성격의 문서이며 재고 출고는 별도로 확정한다. [미국 상무부 Pro Forma Invoice 안내](https://www.trade.gov/pro-forma-invoice) |
| 한글 Invoice | 문서번호·발행일, 공급자·거래처, 품목·규격·수량·단가·공급가액·세액·총액, 통화·결제 조건·비고를 한글로 표시한다. 확정된 출고의 일부 또는 전체 품목을 연결하고, 중복 청구를 검증한다. |
| 거래명세표 | 제공 양식의 날짜·문서번호·공급자/공급받는자·합계 금액·품목 표·작성/검토/승인/인수자란을 반영한다. 공급자 보관용과 공급받는자 보관용을 같은 데이터에서 발행한다. 양식을 인쇄하여 받은 인수 서명과 시스템 내 발행자를 구분해 표시한다. |

인감은 HR Flow의 **서류 발급 → 회사 서류 템플릿**에 등록된 같은 회사의 원본을 사용한다. 서버가 `officialLetterSettings/{companyId}`에서 인감 경로와 출력 치수를 읽고, 인감 포함 발행 권한을 확인한 뒤 PDF에 합성한다. 등록된 인감이 없는 회사에는 기존 설정 화면으로 안내한다. 문서에는 발행 당시의 공급자·거래처·품목·금액·인감 버전과 치수를 고정하고, PDF는 비공개로 저장한다. 거래처나 인감이 변경돼도 기존 발행본은 그 발행 당시 내용으로 열 수 있어야 한다.

문서는 **초안 → 발행 → 정정 또는 취소** 상태를 갖는다. 회사·종류별 번호를 서버에서 발행 시점에 확정하고, PDF 생성이 실패하면 같은 번호와 발행본으로 재시도한다. Proforma 발행, Invoice 출력, 거래명세표 재다운로드는 동일 거래를 다시 출고 처리하지 않는다.

## 5. 개발 단계와 완료 기준

| 단계 | 개발 범위와 산출물 | 다음 단계로 넘어가는 기준 |
| --- | --- | --- |
| **0. 업무 기준과 양식 확정** | 회사별 기초재고와 거래별 입출고 Excel 양식, 업로드·회사별 DB 반영 규약, 문서 3종 시안, 권한표와 기준일 입력 규칙을 작성한다. | Mockup 106행과 K~T 합계로 구조를 검증한다. 창고 공란·음수의 오류 처리, 회사별 자유로운 품목·가격 입력, 원가·통화·반올림·한영 출력 필드를 확정한다. |
| **1. ERP 진입과 기준정보** | 브랜드 오른쪽 ERP 버튼과 `/erp` 보호 경로, 회사별 품목명·매입/판매 단가·창고·거래처 등록/수정/사용 중지, 품목명·코드 검색 및 현재고 조회를 구현한다. | 데스크톱·모바일에서 ERP에 진입한다. 거래처가 DB에 보존되어 검색·재사용 가능하다. 회사별 동일 코드는 독립적으로 관리된다. 권한 없는 자료 접근을 차단하며 재고 미등록과 실제 0을 구분한다. |
| **2. 기초재고와 입출고 원장** | 총괄표 이관과 거래별 Excel 업로드, 미리보기·행별 오류, 직접 입력, 확정·취소·반품·조정 및 중복 방지를 구현한다. 거래 초안과 함께 신규 거래처를 자동 등록하고 기존 거래처를 검색·선택하는 연결 흐름을 구현한다. | 기준일 재고 대사가 일치한다. 미리보기의 예상값과 확정 결과를 비교할 수 있다. 같은 파일·동시 확정·일부 실패를 재시도해도 중복 반영과 초과 출고가 발생하지 않는다. |
| **3. 품목별 입출고 총괄과 상세** | 기간·품목·창고 검색, 입고수량과 단가, 출고 상세, 잔량·잔액·매출·마진 표시 및 Excel 내려받기를 구현한다. | 화면·Excel·원장의 기초/입고/출고/기말 합계가 일치한다. 총괄에서 한 품목을 선택하면 해당 기간의 거래를 추적할 수 있고, 권한 없는 사용자에게 원가·마진이 노출되지 않는다. |
| **4. Invoice와 거래명세표 발행** | 영문 Proforma Invoice, 한글 Invoice, 거래명세표 두 보관용을 PDF로 발행한다. 발행 당시 정보, 기존 인감 이미지, 번호와 개정본을 보관한다. | A4 출력에서 글자·표·인감이 잘리지 않는다. VAT 포함 단가와 세금·합계가 일치한다. 인감 변경 전후 발행본이 구분되고, 인감 없는 회사·무권한 다운로드·재발행 시 중복 출고가 모두 예상대로 동작한다. |
| **5. 시범 운영과 서비스 배포** | 합성 데이터로 검증한 뒤 지정 회사에서 이관을 모의 실행한다. 담당자가 원본 장부와 차이를 대사하고, 서버·규칙·인덱스 적용 후 Cloudflare 웹을 배포한다. | GitHub 빌드·타입·린트·회귀 검사, Emulator 권한·동시성 검사, 데스크톱·모바일 흐름이 통과한다. 시범 회사가 첫 재고 반영과 문서 출력을 확인한 뒤 적용 회사를 확대한다. |

**1단계 구현 범위.** 이번 요청에 따라 기준정보 관리와 품목 검색 시 현재고 표시를 구현했다. 회사 관리자는 기준정보·단가를 관리하고, 일반 회사 사용자는 수량만 조회한다. 거래 초안의 거래처 자동 등록·선택은 실제 거래 입력 화면이 만들어지는 2단계에 연결한다. 단계 1의 재고 조회는 준비되었으며, 실제 회사의 기초재고·입출고를 DB에 확정하는 기능은 2단계다. [1단계 구현과 검증 명세](erp-phase1.md)

**구현 현황.** 작성한 두 `.xlsx` 양식의 검증·미리보기·회사별 확정과 원본 보관에 이어, 원거래를 보존하는 문서 취소·판매반품·매입반품·실사 및 장부금액 조정을 구현했다. 3단계의 기간·품목·창고 조회, 품목별 상세 원장, 순입출고·조정·기말·매출마진 대사, 전체 조회 범위의 Excel 내려받기도 연결했다. 원가 평가 방식은 품목·창고별 이동평균이다. 후속 거래가 있는 문서 전체 취소는 제한하며, 소급 재평가·창고 이동·일반 입출고 수동 입력은 별도 후속 범위다. [2단계 업로드](erp-phase2.md), [취소·반품·조정과 3단계 명세](erp-phase3.md)

**4단계 구현 범위.** 영문 Proforma Invoice, 한글 Invoice, 거래명세표의 공급자·공급받는자 보관용 PDF를 구현했다. 회사 서류 템플릿의 인감 원본과 mm 치수를 재사용하고, 발행 당시 공급자·거래처·품목·가격·조건·인감을 고정한다. 회사 관리자는 초안 저장·미리보기·발행·다운로드·취소·정정 초안을 처리한다. 한글 Invoice와 거래명세표는 확정 출고의 부분 또는 전체 수량을 연결하며 같은 종류의 초과 발행을 차단한다. 모든 문서 작업은 재고 원장을 변경하지 않는다. [4단계 구현과 검증 명세](erp-phase4.md)

## 6. 기존 기능 재사용과 검증 계획

- **화면·권한.** `Sidebar.tsx`의 브랜드 행, `WorkspaceShell.tsx`의 모바일 헤더, `App.tsx`의 보호 경로를 활용한다. 서버는 `security-context.js`의 회사 확인을 재사용하고 ERP 권한을 추가한다. 품목·거래처·확정 원장·잔액·발행본·업로드는 회사 경로 아래 분리하고, 기존 회사 삭제·보관 처리에 새 ERP 데이터와 비공개 파일도 포함한다.
- **업로드.** `payroll-import-files.js`의 압축 항목·실제 압축 해제 크기·외부 연결 검사와 `payroll-workflow.js`의 검증 후 확정 흐름을 참고한다. 설치된 `read-excel-file`과 `yauzl`을 먼저 활용한다. 급여 파서의 단일 시트 제약과 ERP의 서식별 입력 범위는 별도로 관리한다. 매크로·외부 참조·암호화 파일과 허용 범위 밖의 파일은 검증 단계에서 거절한다. [read-excel-file 공식 저장소](https://github.com/catamphetamine/read-excel-file) · [OWASP 파일 업로드 지침](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)
- **PDF·인감.** 기존 공문 서비스의 회사 템플릿·비공개 이미지·발행 스냅샷과 PDFKit 기반 한글 폰트·인쇄 검증을 재사용한다. 출력 양식별로 페이지를 실제 렌더링해 한영 혼합, 긴 품목명, 여러 페이지, 실제 크기 인감, 공급자용·공급받는자용 제목을 점검한다. [기존 회사 서류 기능](official-letters.md)
- **핵심 검증.** 같은 품목에 동시 출고, 업로드와 수동 입력의 중복, 다른 회사 파일 접근, 권한 회수 후 다운로드, 소급·반품·취소, 선행 0이 있는 품목코드, 공란·음수 기말재고, 외화와 세금 포함 단가, PDF 생성 실패 후 재시도를 검사한다. 양식 검증용 자동화에는 제공 자료의 열 구조만 옮긴 합성 파일을 사용한다.
- **운영.** ERP를 시범 회사부터 활성화하고 이관 파일의 기준일·반영 건수·재고금액을 기록한다. 문제가 생기면 ERP 활성화를 중지하고, 이미 확정한 재고는 원장을 보존한 상태에서 조정으로 복구한다. 서버와 웹의 배포는 기존 운영 절차를 따른다. [Cloudflare 운영 배포](cloudflare-deployment.md)

0단계의 **회사별 기초재고 및 거래별 입출고 표준 Excel 양식**과 업로드 규약을 작성했다. 실제 입력 시트는 비워 두고 Mockup·예시는 별도 시트로 분리했다. 1단계의 회사별 기준정보·현재고 조회, 2단계 Excel 검증·미리보기·확정, 취소·반품·조정과 3단계 총괄·원장·Excel 출력에 이어 4단계 거래서류 PDF·인감 재사용을 구현했다. **5단계 시범 운영과 서비스 배포**를 시작했으며 운영 코드 배포와 지정 회사의 첫 실제 장부 대사·실물 인쇄 확인을 구분해 진행한다. 이후에는 ERP 전용 백업·복원과 운영 관측을 보강한다.
