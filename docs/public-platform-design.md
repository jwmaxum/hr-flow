# 랜딩·플랫폼 관리 화면 디자인

2026-10-29부터 공개 랜딩과 SYSTEM_ADMIN의 플랫폼 관리 센터에도 기존 업무 화면의 색상 토큰, SUIT Variable, 공통 UI 컴포넌트를 적용한다.

- 색상·폰트 원본: `client/src/styles/WorkflowTheme.css`
- 공통 버튼·입력·패널: `client/src/components/ui/index.tsx`
- 화면별 스타일: `LandingPage.css`, `SuperAdminDashboard.css`에 범위를 한정한다.
- Primary 500은 강조 장식에, Primary 800은 흰 글자의 주요 버튼과 작은 강조 글자에 사용한다. 상태는 기존 Semantic 토큰을 사용한다.

## 유지한 기능

랜딩의 로그인·체험 버튼, 기능 안내/설명서 탭과 키보드 이동, 설명서 목차·권한표·참고 링크를 유지한다. 공용 ProductGuide와 안내 데이터는 변경하지 않는다.

플랫폼 관리의 조직 검색·상태 변경·조직별 사용자, 전체 사용자, 비밀번호 초기화, 세액표 업로드, 결제 내역, 재인증 후 구독 연장·조직 삭제를 유지한다. 기존 조회·상태·처리 함수는 유지하며, 플랫폼 경로에 공통 셸을 적용하는 것은 화면 표시만 바꾼다. 플랫폼 화면에는 회사 업무 알림을 추가하지 않는다.

모바일에서는 조직 카드와 동작 버튼을 줄바꿈하고 결제 표 안에서만 가로 스크롤한다. 확인 창은 화면 높이 안에서 스크롤하며 브라우저 기본 모달의 포커스 제한을 사용한다.

## 폰트와 초기 로딩

랜딩에서 SUIT를 사용하므로 공통 테마 CSS를 최초 공개 화면에서도 불러온다. 로컬 `/fonts/SUIT-Variable-2.0.5.woff2`와 `font-display: swap`을 사용한다. 이전 로딩 최적화 단계에서 기록한 ‘익명 랜딩은 SUIT를 요청하지 않음’은 당시 버전의 측정값이며 이번 디자인부터는 해당하지 않는다. 업무 화면·Excel·ZIP·플랫폼 관리 코드는 기존 지연 로딩 구조를 유지한다.

## 검증과 배포

- 빌드의 `tsc -b`, ESLint, 클라이언트 단위 및 기존 관리자·결제·인증·경로 회귀 검사
- 합성 자료를 사용한 실제 컴포넌트의 1440/390/320px 레이아웃·기능·키보드 검증
- `npm run test:e2e`: 로컬 Firebase Emulator에서 공개 랜딩, 역할별 로그인, 첨부파일과 조직 격리 검증. 운영 자료는 사용하지 않는다.
- `npm run test:e2e:boundary`: 테스트 설정이 운영 빌드에 포함되지 않았는지 확인

웹은 `jwmaxum/hr-flow`의 `main`으로 새 Cloudflare 주소 `hr-flow-chj.pages.dev`에 배포한다. 이번 디자인 변경에는 Firebase 백엔드 배포가 필요하지 않다. 기존 `hr-flow.pages.dev`는 웹 파일 해시를 비교해 이전 버전 유지 여부를 확인한다.
