# ERP 취소·반품·조정과 기간별 총괄·상세 원장

2026-11-12. 2단계 Excel 확정 원장에 연결되는 거래 처리와 개발계획서 3단계 조회·Excel 내려받기를 구현한다. 모든 데이터는 로그인한 회사에 속하며 참고 Mockup을 운영 자료로 등록하지 않는다. 운영 배포는 이 작업에 포함하지 않는다.

## 사용 흐름

1. **ERP → 입출고 총괄·원장**에서 기간·품목명/코드·창고를 선택해 조회한다. 시작일은 기초재고 마감일 다음 날부터다.
2. 총괄은 품목·창고별 기초, 순입고, 순출고, 조정, 기말 수량과 금액을 표시한다. 회사 관리자는 평균입고단가·순매출·순매출원가·매출마진도 확인한다. 수량 합계는 단위별로 구분한다.
3. 총괄 행의 **상세 원장**을 누르면 같은 기간·품목·창고로 거래일, 처리순서, 문서, 입출고·취소·반품·조정, 잔량·잔액과 연결 문서를 조회한다. 상세 잔량·잔액은 해당 행의 품목·창고 누적값이다.
4. 회사 관리자는 원거래 행의 **반품**, **문서 취소**, 상단 또는 총괄 행의 **재고 조정**으로 처리한다. 사유·처리일을 입력하고 전후 수량·금액을 검토한 다음 확인란을 체크하여 확정한다.
5. **전체 Excel 내려받기**는 화면에 불러온 첫 100행만이 아니라 조회 조건 전체를 실제 `.xlsx`로 내보낸다. 총괄 또는 상세 시트, 조회 기준·금액 합계 시트, 단위별 수량 시트를 함께 제공한다.

## 거래 처리 규칙

### 전체 취소

- 확정 원장과 원본 파일을 삭제·수정하지 않는다. 반대 부호의 원장 행, 원거래 연결, 사유·작성자·확정자를 새로 기록한다.
- 일반 입출고는 선택 행이 속한 문서 전체, 기초재고는 해당 업로드의 기초 원장 전체, 조정·반품은 해당 처리 전체를 취소한다. 최대 200행이다.
- 관련된 모든 품목·창고에서 해당 문서가 마지막 거래여야 한다. 다른 품목의 후속 거래는 허용한다. 같은 문서에서 같은 품목이 여러 번 나왔다면 역순으로 복원한다.
- 원거래에 유효한 반품이 연결되어 있으면 원거래 전체 취소를 막는다. 최신 반품 자체를 취소하면 해당 원거래의 반품 가능 수량을 복원한다. 취소 역거래를 다시 취소하는 방식은 지원하지 않는다.
- 기초재고 취소도 최초 기준일과 감사 원장은 보존한다. 취소일의 조정 열에 감소분을 반영하며, 이후 올바른 재고는 실사 조정으로 기록한다.

### 반품

- **판매반품:** 원출고 행의 판매금액·세액과 실제 출고원가를 수량에 비례해 되돌린다. 누적 수량의 반올림 차이를 사용하여 부분반품을 반복해도 원거래 금액을 초과하지 않고, 전량 반품하면 원래 금액과 일치한다.
- **매입반품:** 현재 품목·창고의 이동평균 원가로 재고를 차감한다. 원매입 단가에 따른 공급가·세액 및 원화 공급가 환불액은 별도로 보존·표시한다. 예를 들어 현재 평균원가가 150원이고 원매입 단가가 200원인 품목 3개를 반품하면 재고는 450원 감소하고 원매입 공급가 환불액은 600원이다.
- 누적 반품수량은 원거래 수량 이하이며, 매입반품은 현재고를 초과할 수 없다. 취소한 원거래, 다른 회사 행, 유형이 다른 원거래에는 반품을 연결하지 않는다.
- 이 기능은 재고 처리다. 실제 결제 환불, 세금계산서 또는 회계 전표 발행을 자동 실행하지 않는다.

### 실사·금액 조정

- **실사 수량 조정:** 실제 총수량을 입력한다. 증가분에는 사용자가 증가 재고금액을 명시하며, 감소분은 현재 이동평균 원가로 계산한다. 전량 차감하면 남은 장부금액 전부를 차감한다.
- **장부금액 조정:** 수량은 유지하고 조정 후 총 장부금액을 입력한다. 음수 수량·금액, 수량 0에 금액이 남는 처리는 거절한다.
- 모든 처리에 3~500자의 사유가 필요하다. 처리일은 기초 기준일 다음 날부터이며 회사의 마지막 확정일보다 과거로 입력할 수 없다. 같은 날짜의 다음 처리순서는 서버가 부여한다.
- 기존 확정 뒤의 원가를 재계산하는 소급 처리와 창고 이동, 일반 입출고의 수동 입력은 이번 범위에 포함하지 않는다.

## 집계와 권한

기초는 시작일 직전의 확정 원장 잔액이다. 기간 안의 원거래와 역거래를 모두 합산한다. 취소 상태라는 이유로 원거래를 집계에서 빼지 않는다.

`기초 + 순입고 − 순출고 + 조정 = 기말`

판매반품·출고 취소는 순출고와 순매출·순매출원가를 감소시킨다. 매입반품·입고 취소는 순입고를 감소시킨다. 평균입고단가는 순입고금액을 순입고수량으로 나누며 순수량이 0 이하이면 표시하지 않는다. 따라서 개별 거래 단가는 상세 원장에서 확인한다.

`매출마진 = 원화 순매출 − 순매출원가`

실사손익·장부금액 조정·매입반품 원가차이는 이 매출마진에 합산하지 않는다. 외화 거래의 금액 열에는 통화를 표시하고 총괄은 기존 확정 원화금액을 사용한다.

현재 회사 `ADMIN`만 처리·금액 조회가 가능하다. `MEMBER`·`SUB_ADMIN`은 수량 조회와 수량 Excel만 가능하며 서버에서 단가·원가·매출·마진·환불액·거래처·비고를 제거한다. 플랫폼 `SUPER_ADMIN`의 회사 원장 접근은 허용하지 않는다. 상태·세션·회사 소속·사용기간을 매번 검증한다. 브라우저의 Firestore 직접 접근은 차단한다.

미리보기는 품목·창고·현재고·누적 반품수량·회사 원장 상태를 포함한 지문을 저장한다. 확정 시 트랜잭션 안에서 재계산하며, 변경되었으면 새 미리보기를 요구한다. 원장·재고·반품수량·취소 연결·감사기록은 한 번에 저장한다. 같은 요청 재시도는 같은 확정 결과를 반환한다.

조회 페이지와 Excel은 동일한 집계 함수를 사용한다. 원장 버전 또는 품목·창고 표시 정보가 바뀌면 이어 보기와 이전 화면 기준의 내려받기를 거절하고 새 조회를 요구한다. 사용자 문자열은 Excel 문자열 셀로 기록하므로 `=`, `+` 등으로 시작하는 값도 수식으로 실행되지 않는다.

## 저장 구조와 운영 범위

- 신규 callable: `manageErpCorrection`, `manageErpReport`.
- 신규 회사 하위 컬렉션: `erpCorrections`(미리보기·확정 처리), `erpMovementLinks`(누적 반품수량·취소 연결).
- 기존 `erpMovements`, `erpDocuments`, `erpInventory`, `erpState`, `erpAudit`와 연결한다. 회사 삭제 절차에 신규 컬렉션을 포함한다.
- 2단계의 기존 원장 형식도 조회·취소·반품 대상이다. 이후 Excel 업로드는 확정 시 거래처·창고 이름도 원장에 보존한다.
- 조회는 한 번에 과거부터 종료일까지 관련 원장 최대 20,000행, 화면은 100행씩, Excel은 최대 5,000행 및 응답 5MiB다. 초과 시 일부 합계를 내보내지 않고 품목·창고 등 범위를 좁히도록 안내한다. 기초 잔액 계산 때문에 시작일 이전 원장도 읽기 한도에 포함된다.
- Firestore 복합 인덱스 4개를 `firestore.indexes.json`에 추가했다. 운영 반영 시 인덱스 생성 완료를 확인한 뒤 함수와 웹을 배포해야 한다. 웹은 기존 Cloudflare Pages 절차를 따른다.

첫 브라우저 실행에서 발견한 조회 조건 비교 문제와 기준정보 저장 대기 문제를 수정한 뒤, 코드 변경을 멈추고 데스크톱·모바일 8건을 전부 재실행해 통과했다. 검증된 예에서는 기초 10개·1,000원에서 입출고, 판매반품, 매입반품, 실사 조정·취소, 금액 조정을 거쳐 기말 **14개·2,000원**, 순매출 **900원**, 매출마진 **450원**이 화면과 Excel 모두 일치했다. 두 화면의 캡처를 확인했고 모바일 페이지 너비 초과도 없었다.

이는 요청 범위에 맞춘 로컬 검증 결과이며 전체 애플리케이션의 모든 브라우저 시나리오를 실행한 것은 아니다. 운영 DB에 시험 자료를 쓰거나 Git push·운영 배포를 실행하지 않았다. 서비스 반영에는 위 인덱스, Firebase Functions 및 Cloudflare 웹 배포와 운영 확인이 필요하다.

다음 개발은 4단계의 영문 Proforma Invoice·한글 Invoice·거래명세표 발행과 등록 인감 이미지 재사용이다. 재고 확정과 문서 발행을 분리하여 문서를 재다운로드할 때 출고를 중복 반영하지 않도록 연결한다.
