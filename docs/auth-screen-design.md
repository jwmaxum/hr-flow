# 인증 화면 디자인

2026-10-29 로그인·회원가입·가입 완료, 이메일 인증 후 조직 등록, 일반/최초 비밀번호 변경과 인증 대기·오류 화면에 기존 WorkflowTheme 색상과 로컬 SUIT Variable을 적용했다.

공통 Button·Input·Panel을 재사용하고 각 화면 CSS에 범위를 한정한다. 로그인·프로필 카드는 최대 480px, 비밀번호 변경 창은 최대 440px이며 모바일에서는 필드·버튼을 한 열로 배치한다. 작은 텍스트와 주요 버튼은 Primary 800을 사용한다. 처리·오류·인증 상태, 연결된 입력 레이블과 키보드 포커스를 제공한다.

## 인증 동작 유지

- 로그인은 기존 이메일 정규화와 역할별 이동, 인증 오류 처리를 유지한다. 공통 임시 비밀번호로 로그인할 수 있도록 로그인 입력에 새 최소 길이 제한을 추가하지 않았다.
- 회원가입은 기존 12~128자 정책과 일치 검사, 이메일 인증 발송, 비밀값을 제외한 회사 정보 임시 저장을 유지한다.
- 조직 등록은 인증된 이메일을 다시 확인한 뒤 서버에 회사 이름과 관리자 이름만 전달한다. 회사 ID·권한·소유자는 기존 서버에서 결정한다.
- 일반 비밀번호 변경은 현재 비밀번호 재인증 → 토큰 갱신 → 서버 변경 → 로그아웃 순서를 유지한다. 최초 변경의 업무 접근 차단도 유지한다.
- 비밀번호 창은 기본 모달로 포커스를 제한하고 닫으면 호출 버튼으로 복원한다. 필수 변경은 닫기/Escape를 차단하고, 처리 중에는 일반 변경도 닫을 수 없다.

상태·검증·인증 API·이메일 인증·회사 생성 처리 코드는 기존 버전과 비교한다. Auth store·서비스·업무 경로 권한·Firestore/Storage 보안규칙은 디자인 변경 범위에 포함하지 않는다.

## 검증

- 1440/390/320px 합성 자료 브라우저 검사: 로그인, 회원가입, 프로필 인증 대기/완료, 일반/필수 비밀번호 변경, 로딩 화면
- 실제 컴포넌트의 폼 검증·역할별 이동·서버 호출 순서·포커스·처리 잠금·계정 전환 시 입력 초기화
- `npm run test:e2e`: 고정된 demo Firebase Emulator에서 로그인·첨부·격리 검사와 일반/최초 비밀번호 변경, 이전 비밀번호 거부 및 새 비밀번호 재로그인
- 테스트용 최초 변경 계정만 매 실행 무작위 7자 초기 비밀번호를 사용하여 짧은 임시 비밀번호 로그인 동작도 확인한다. 운영 계정·암호는 사용하지 않는다.
- 빌드/타입·린트·단위·관리자/인증/결제 회귀 검사, 배포 빌드의 E2E 경계 검사

웹 배포는 `jwmaxum/hr-flow` → 새 Cloudflare 주소 `hr-flow-chj.pages.dev`만 대상으로 한다. 기존 주소 `hr-flow.pages.dev`는 배포 전후 해시로 유지 여부를 확인한다. 이번 디자인에는 Firebase 백엔드 배포가 필요하지 않다.
