# 급여대장·연간 급여명세서

## 사용 절차

회사 SUPER_ADMIN·ADMIN은 급여관리에서 대상 연도와 월을 선택하고 직원별 연봉/월급, 비과세액, 공제대상 가족 및 8~20세 공제대상 자녀를 확인한다. 저장되는 금액은 연봉 기준이며 월급 입력은 12배하여 저장한다. 퇴직금 포함 선택은 제공하지 않는다. 이전 포함 설정이 남은 직원은 관리자가 금액을 검토하고 설정을 저장해야 확정할 수 있다. 금액을 자동으로 바꾸거나 과거 승인액을 재계산하지 않는다.

본부·팀·이름 필터와 화면 합계는 조회 목록의 예상액이다. **회사 전체 급여 확정**은 검색 조건과 관계없이 서버가 읽은 회사 전체의 저장 설정으로 처리한다. 확인창은 전체 인원, 지급·공제·실지급 합계, 0원 급여 인원 및 세액표 출처를 표시한다. 확인 이후 급여·조직·재직 상태·세액표가 바뀌면 승인을 중단하고 최신 미리보기를 다시 요구한다.

확정 이후 **월별 급여대장 PDF**를 다운로드한다. 해당 연도와 직원을 선택하면 **연간 급여명세서 PDF**를 다운로드할 수 있다. 현재 직원뿐 아니라 과거 확정 자료에 남은 퇴사자도 선택할 수 있다. 메일 발송 기능은 제공하지 않는다. PDF를 외부 PDF 프로그램에서 열어 인쇄한다.

급여는 현재 저장된 설정에 따른 한 달 전체 금액이다. 입사 전 월·퇴사 계정은 새 확정 대상에서 제외한다. 정지 상태의 재직자는 급여 대상에서 자동 제외하지 않는다. 중도 입·퇴사 일할 계산이나 보험 가입 예외를 자동 추정하지 않는다. 해당 정보가 별도 인사 필드로 관리되지 않는 직원의 사번·직급·퇴사일은 빈칸으로 둔다.

## 저장된 금액과 PDF

- `managePayroll`이 `payroll_records`에 회사별·연월별 한 개의 schemaVersion 2 승인 자료를 생성한다. 직원별 신원·소속·지급/공제액·합계·승인자·승인시각·세액표 출처를 저장한다.
- 새 상세 승인 자료는 클라이언트에서 생성·수정·삭제할 수 없다. 같은 회사의 같은 월에 중복 확정할 수 없다. 과거 급여 정정과 재승인 이력 기능은 후속 범위다.
- 연간 명세서는 월별 승인 당시의 상세 금액만 합산한다. 미승인 월은 `미확정`, 이전 집계만 있는 월은 `상세 내역 없음`으로 표시하며, 현재 급여 설정으로 과거 수치를 채우지 않는다.
- 이전 집계 기록의 조회·삭제는 유지한다. 집계 기록에는 직원별 금액이 없어 월별 급여대장 PDF를 만들 수 없다. 이후 생성한 상세 기록은 이전 웹 버전의 이력 화면에 필요한 합계·승인시각 필드도 함께 저장한다.
- PDF는 승인 자료에서 서버가 생성하여 인증된 호출자에게 반환한다. A4 가로형, 한국어 글꼴 포함, 다중 페이지 머리글·합계·페이지 번호를 지원한다. PDF 파일 자체를 공개 URL에 게시하거나 메일로 전송하지 않는다.

## 세액표와 계산 기준 점검 (2026-10-29)

운영 `system_config/tax_table`을 읽어 확인한 결과, 등록 파일명은 `근로소득 간이세액표_2026.03.01.xlsx`였다. 기존 업로더가 설명 행을 세율 구간으로 오인하고 같은 하한의 첫 행을 남기면서 **월 과세급여 450만·700만 원 구간 두 행을 유실**했다. 나머지 644개 일반 구간과 1,000만 원 기준세액은 공식표와 일치했다. 종전 계산은 누락 구간만 내장표로 보완했고 고소득 기준세액도 내장표를 사용하므로 업로드 표 전체가 적용되는 상태는 아니었다.

새 업로더는 전체 770~10,000천원 구간의 연속성, 상·하한, 가족 수별 11개 정수 세액, 중복 충돌과 1,000만 원 기준세액을 검사한다. 설명 행은 수치 구간 중복 제거 전에 제외한다. 잘못된 표는 저장하지 않는다. 기존 잘못된 표를 읽으면 부분 혼합 계산 대신 전체 공식 기본표로 대체하고 화면·승인 자료에 출처와 원인을 기록한다. 유효한 업로드 표는 고소득 기준세액에도 사용한다.

사용자 승인 후 원본을 로컬과 서버에 백업하고 점검 당시 updateTime·해시 조건을 적용한 원자적 복구를 완료했다. 누락된 두 행은 공식표에서 복구하고 설명 행 다섯 개는 제외했다. 정상 644개 행·1,000만 원 기준세액·기존 승인 급여는 변경하지 않았다. 사후 조회에서 646개 정상 구간과 고소득 기준세액의 공식표 일치, 업로드 출처 사용을 확인했다. 원본은 접근 규칙을 추가하지 않은 `system_config_tax_backups/repair-20261029-c9a4a19d64d59f98`에 보관하며, 서비스 클라이언트가 이 백업을 읽거나 쓸 권한은 부여하지 않는다.

사용자가 기존 잘못된 승인건의 정정도 승인하여 운영 이력의 스키마·직원별 상세자료 보유 여부를 추가 점검했다. 기존 4건은 모두 직원별 상세자료가 없는 이전 집계였으며 상세 승인 자료는 0건이었다. 따라서 직원별 오류 금액을 검증·복원할 근거가 없어 합계 수치는 덮어쓰지 않았다. 새 화면은 이 기록을 `상세 내역 없음`으로 구분하며 연간 직원별 금액에 포함하지 않는다. 당시 실제 급여대장 등 원자료를 확보한 이후 정정·재승인 절차로 처리해야 한다.

브라우저 예상 계산과 서버 승인 계산은 `functions/payroll-calculation.mjs`를 공유하며 양쪽 공식 JSON 자료도 동일하다. 현재 확정 지원 기간은 **2026년 3~12월**이다. 지원하지 않는 과거·미래 기간의 새 승인을 차단하고 저장된 과거 PDF 열람은 유지한다.

## 권한·조직 격리

실제 저장 역할 ADMIN인 회사 관리자만 API를 이용한다. 역할 표시명 변경은 하지 않는다. SYSTEM_ADMIN·SUB_ADMIN·MEMBER에게 회사 급여 API 권한을 추가하지 않는다. 회사 ID는 요청에서 받지 않고, 철회·정지·퇴사·비활성·초기 비밀번호 상태·만료된 구독을 서버에서 확인한다. 승인 트랜잭션과 PDF 반환 직전에도 권한과 자료 변경을 다시 검사한다.

타 회사 문서 ID·직원 ID·회사 ID·합계·직원 목록·조직 필터를 주입하는 요청을 거부한다. 응답과 PDF에는 급여에 필요한 항목만 포함하고 주민번호·주소 등 인사 원본을 복사하지 않는다. 회사·계정 전환 시 화면을 초기화하고 진행 중인 응답과 다운로드도 세션 범위를 다시 확인한다.

회사 삭제는 기존 관리자 서버 절차가 상세 급여 자료까지 지우고 회사 ID 재사용 방지 tombstone을 남긴다. 직원 계정 삭제만으로 해당 회사의 승인 급여 자료를 다시 계산하거나 지우지 않는다.

## 검증 실행

`npm --prefix client run build`, `npm --prefix client run lint`, `npm --prefix client run test:unit`과 인증·관리자 UI 회귀 테스트를 실행한다. `npm run test:e2e`는 외부 자격증명을 제거한 demo 프로젝트에서 보안규칙, 급여 서비스·PDF 테스트 및 실제 로그인·설정 저장·미리보기·승인·PDF 다운로드·조직 격리 데스크톱/모바일 검증을 순서대로 수행한다. 별도 `npm run test:payroll`은 Firestore 에뮬레이터가 필요하다.

최종 검증: 빌드·TypeScript·린트 통과, 클라이언트 단위 43건·권한/화면 회귀 52건·보안규칙 880건·급여 서버/PDF 33건·기존 4개 보안 API 회귀 통과. 실제 Firebase 에뮬레이터 로그인·첨부파일·급여 확정·월별/연간 PDF·조직 격리 브라우저 14건(데스크톱 7·모바일 7)이 통과했다. 별도 실제 컴포넌트 15그룹 및 전체/불완전 세액표 업로드, 1440·390·320px 화면과 PDF A4 규격을 검증했다. 급여 서비스 줄 커버리지 98.71%는 해당 모듈 범위이며 저장소 전체 커버리지가 아니다. 초기 병렬 부하와 로컬 에뮬레이터/브라우저 실행 환경에서 실패한 실행은 성공으로 계산하지 않았고, 환경을 바로잡은 순차 최종 실행의 실제 종료코드 0으로 판정했다.

배포 시 `managePayroll` 함수와 Firestore 규칙을 먼저 배포한 뒤 `jwmaxum/hr-flow` main을 푸시한다. 새 Cloudflare 주소 `hr-flow-chj.pages.dev`의 배포 체크와 공개 파일을 검증한다. 기존 `hr-flow.pages.dev` 웹 파일·배포 연결은 변경하지 않는다.

## 첨부 엑셀 재대조 및 국민연금 연령 기준 (2026-10-29)

실제 제공된 `근로소득 간이세액표_2026.03.01.xlsx`를 읽어 재검증했다(원본 SHA256 `66e2d1a24a10d91e28f2c5dd2ede63871b105e1dc4adebb001a13265bec42737`). `근로소득간이세액표`의 646개 급여 구간×11개 가족별 세액과 1천만 원 기준 11개 세액이 내장 자료·실제 엑셀 업로드 파서 결과와 일치했다. C652·C654·C656·C658·C660·C662의 6개 고소득 산식도 대조했다. 소액 부징수 후처리까지 포함한 독립 Decimal 계산 29,273건으로 구간 경계 ±1원, 가족 1~12명·44~100명, 자녀 0~3명 및 실제 표에서 확인한 저액 사례 33건을 검증했다.

고소득의 가족 11명 초과 공제에서 기준세액을 먼저 0으로 제한하면 가족 공제 일부가 소실되는 오류를 수정했다. 이제 고소득 가산과 가족·자녀 공제를 모두 적용한 최종 세액에서만 0 미만 및 10원 미만 끝수를 처리한다. 첨부 보조 `Sheet1`은 수식이 아닌 고정 예시이며 일부 연 환산·자녀공제·합계·절사 값이 공식 기준과 달랐다. 이 비교 예시를 법정 세액표나 보험 기준으로 채택하지 않으며 원본 파일은 수정하지 않는다. 고정 회귀 fixture에는 공개 세액과 출처 해시만 포함하고 보조 예시의 직원·회사 정보나 사적 급여 자료는 복사하지 않는다.

엑셀에 별도로 적혀 있지 않은 [소득세법 제86조의 소액 부징수](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1021862057)도 적용한다. 일반 근로소득 원천징수세액이 최종 공제 후 1,000원 미만이면 소득세를 0원 처리하고, 그 소득세로 계산하는 지방소득세도 0원이 된다. 정확히 1,000원은 징수한다. 공개 표의 과세월급여 228만원·가족 2명·공제대상 자녀 1명은 표 세액 21,520원에서 자녀공제 20,830원을 뺀 690원을 징수하지 않는다. [국세청 세액계산 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7701&mi=2340)도 함께 확인했다.

국민연금은 등록된 인사정보 `UserProfile.rrn`의 생년월일 6자리와 뒤 첫 세기 구분 숫자만 해석하여 선택한 급여 월의 의무가입 여부를 판단한다. 뒤 여섯 자리가 마스킹되어도 계산할 수 있다. 세기 구분이 없거나 가려진 값, 잘못된 날짜, 미래 생년월일, 미등록 값은 만 60세 미만으로 가정하여 기존 공제를 유지한다. 증명서에 입력한 생년월일이나 다른 회사의 인사정보를 가져오지 않는다. 인사 입력란과 산출 상세에서 이 기준을 안내한다.

공단의 자격상실·월별 부과 원칙과 민법 연령 계산 규정을 적용하여, 급여 월 초일이 60번째 생일 이상인 월은 국민연금을 0원 처리한다. 보통 생일이 속한 달까지 공제하고 다음 달부터 제외하며, 1일생은 생일 월부터 제외한다. 예를 들어 1966-11-01생은 2026년 11월부터, 1966-11-02생은 12월부터 제외한다. 이 경계는 공단 예시를 그대로 인용한 것이 아니라 아래 자격상실·기간 규정의 적용 결과다. 임의계속가입 등 별도 가입 예외 기능은 추가하지 않았다.

국민연금 제외 시 다른 보험료·근로소득세·지방소득세 계산은 유지하고 공제 합계·실수령액을 재계산한다. 브라우저 예상액과 서버의 저장된 인사정보 기반 승인액이 같은 계산 모듈을 사용한다. 주민번호·생년월일은 계산 결과·승인 자료·목록 API·월별/연간 PDF에 새로 저장하거나 표시하지 않는다. 기존 승인액은 현재 인사정보로 자동 재계산하지 않으며, 새 승인 자료에 계산된 국민연금 금액을 저장하고 PDF는 그 저장 금액을 출력한다.
