# 출고 문서 통합 관리

ERP의 ADMIN용 `출고 문서 관리`에서 확정 출고 문서를 선택한다. 출고 확정 완료 화면의 `이 출고 문서 통합 관리`도 같은 화면으로 연결된다.

## 조회와 처리

- 출고 기간, 문서번호·거래처, 미수/입금완료/환불 확인 상태로 조회한다. 기간은 원출고일 필터이며 수금·반품 잔액은 서버의 현재 한국 날짜 기준이다. 오래된 출고도 최근 수금을 포함한 잔액을 표시한다.
- 문서별 부가세 포함 매출, 공급가액, 세액, 배분 수금액, 미수잔액, 지급기일과 연체를 표시한다.
- `수금 등록·내역`: 전액 또는 부분 금액을 입력하고 미리보기·확정한다. 기등록 수금 우선 사용 시 같은 거래처·통화의 미배분 수금을 먼저 배분하고 부족분만 새 입금으로 기록한다. 은행내역 확인은 사용자가 수행한다.
- `반품 처리`: 원출고 품목의 반품 가능 수량을 선택한다. 합성상품은 부모 판매행을 선택하며 출고 당시 구성과 원가로 구성품 재고를 복원한다. 기존 ADMIN 승인·월마감·감사 이력을 유지한다.
- `거래명세표 발행`: 선택 문서에 연결한 초안을 작성하고 등록 인감으로 PDF를 발행·다운로드한다. 해당 출고의 서류만 보관 목록에 표시한다. 발행은 재고나 수금에 영향을 주지 않는다.

반품은 실제 환불을 기록하지 않는다. 반품 완료 후 미수금·반환 예정액을 확인하고 같은 문서의 거래명세표 정정으로 바로 이동한다. 반환 가능 수량과 서류 발행 가능 수량은 다르다. 후자는 이미 발행한 수량도 제외한다.

## 반품 후 정산

반품 미리보기에서 이번 반품금액, 미수금 차감액, 남은 문서 미수금과 거래처 반환 예정액을 확인한다. ADMIN이 확정하면 재고·매출·원가 변동과 초과 배분 해제·잔여 재배분을 하나의 트랜잭션에 반영한다. 다른 출고 문서의 정상 배분과 원수금은 보존한다. 직원 요청은 ADMIN 승인 전에는 재고·배분을 변경하지 않으며 거래처 전체 금융 잔액은 ADMIN에게만 제공한다.

출고 문서 통합 화면에서는 반품 확정 후 **거래명세표 발행·정정** 화면으로 바로 이동하고 정산 결과를 함께 보여준다. 입출고 상세 원장에서 반품한 ADMIN도 완료 화면의 **거래명세표 정정**으로 이동할 수 있다. 반품으로 미수금이 줄어든 금액을 다시 수금으로 기록하지 않으며, 반환 예정액 표시만으로 실제 환불 기록을 생성하지 않는다.

예를 들어 1,100원 출고 중 660원을 반품하면 미수 상태에서는 남은 미수금이 440원이다. 550원을 이미 수금했다면 미수금은 0원, 반환 예정액은 110원이다. 완납했다면 반환 예정액은 660원이다. 이는 같은 거래처의 다른 청구·수금이 없는 단일 문서 예다. 실제 화면에는 문서별 결과와 같은 회사·거래처·통화 전체의 잔액을 구분한다.

발행된 거래명세표를 선택해 정정 사유를 확인하면 원본 취소와 정정 초안을 함께 기록한다. 반품 및 다른 발행본을 제외한 남은 수량으로 새 번호를 발행하며, 전량 반품은 취소만 기록한다. 원본 PDF와 정정 연결을 보존하고 등록 인감을 재사용한다. 실제 환불 등록은 정정의 선행 조건이 아니다. **환불 증빙 첨부는 제공하지 않는다.** 기존 월마감 증빙 기능은 유지한다.

이전 배포에서 발생한 미정리 초과 배분과 실제 지급 기록은 **반품 후 정산 → 기존 배분·실제 반환 기록 (선택)**에서 처리할 수 있다. 기존 수동 해제/환불 이력은 그대로 유지하고 과거 원장을 일괄 재작성하지 않는다. 새로운 반품 확정 시에는 선택 문서의 기존 초과 배분도 미리보기에 포함해 함께 정리한다. 실제 환불 취소는 기존 미수금·수금 관리에서 원환불과 연결해 처리한다.

반품 취소는 원반품을 역거래로 기록하고 미수·반환 한도를 다시 계산한다. 이미 해제된 금액을 임의로 다시 배분하거나 실제 환불을 취소하지 않는다. 마지막 재고·수금·배분일 이전 날짜로 반품할 수 없으며, 미리보기 후 관련 내역이 바뀌면 재검증한다. 원본 발행일이 마감된 거래명세표의 정정에는 ADMIN 재개방이 필요하다. 회사 격리·중복 방지·승인·월마감·변경 이력은 유지하며 새 컬렉션·인덱스·권한을 추가하지 않는다.

## 판매단가와 부가세

출고 행마다 `포함`, `부가세별도`, `면세`를 선택한다. 기존 영세 품목의 0% 과세 구분은 별도로 보존한다. 단가 입력과 총출고금액 입력 모두 동일한 규칙을 적용한다.

| 입력 금액 1,000원 | 공급가액 | 부가세 | 매출액·청구금액 |
| --- | ---: | ---: | ---: |
| 포함 | 909 | 91 | 1,000 |
| 부가세별도 | 1,000 | 100 | 1,100 |
| 면세 | 1,000 | 0 | 1,000 |

매출액(부가세 포함)은 청구·수금 기준 금액이다. 매출총이익은 공급가액 순매출에서 실제 출고 재고원가를 차감한다. 매입세액을 공제받는 일반적인 과세 거래에서 부가세 포함 매출액과 부가세 포함 매입금액의 차액은 회계상 매출총이익과 다르다. 예: 판매 1,100원(공급가액 1,000원), 매입 770원(공급가액 700원)이면 부가세 포함 차액 330원 중 부가세 차액 30원을 제외한 300원이 매출총이익이다. 부가세 공제 여부를 자동 판정하거나 원가에 일괄 10%를 더하지 않는다.

기존 재고원가·월별 순매출·매출총이익 계산과 Excel 입력 규칙은 유지한다. 월별 화면의 부가세 포함 매출액은 통화별로 구분한다.

## 저장과 검증

- `manageErpFinance`의 `shipmentList`/`shipmentDetail`은 인증된 ADMIN의 회사 경로만 조회한다. 한 번에 30건, 스냅샷이 달라지면 첫 페이지부터 재조회한다.
- 기존 `paymentPreview`/`paymentCommit`을 확장해 선택 금액과 수금 방법·참조번호를 검증한다. 기존 전액 확인 API와 호환된다.
- 새 수금, 문서 배분, 상태, 감사 이력을 같은 Firestore 트랜잭션에 저장한다. 미리보기 후 잔액·거래처 변경을 거부하고 동일 확정 요청 재전송을 중복 반영하지 않는다.
- 통화별 최소 금액 단위, 잔액 초과 수금, 회사 경계, 역할, 월마감은 서버에서 검증한다.
- `manageErpDocuments.list`는 회사 하위 컬렉션에서 선택 출고 문서번호로 조회한다. 새 컬렉션·복합 인덱스·권한 확대는 없다.
- 회귀 테스트: 부분 수금·기등록 수금 재배분·동시/중복/오래된 확인·반품/취소 잔액·합성 구성품 원가·원화/외화·혼합 부가세·연결 문서 필터·회사 격리. 브라우저 테스트는 데스크톱/모바일에서 부분 수금→반품→등록 인감 거래명세표 PDF→잔금 수금→추가 반품과 자동 정산→실제 지급 기록 없이 정정 발행을 확인한다. 여러 문서의 혼합 배분 보존·부분 해제/환불·전량 반품 취소·원본 PDF 보존도 서버 회귀 검사에 포함한다.
- 거래명세표·수금·문서 배분 초기 조회 응답은 해당 화면 요청이 유효할 때만 반영한다. 지연된 초기 응답이 발행 완료 화면을 새 초안으로 바꾸거나 수금 후 잔액·지급기일 미리보기를 덮어쓰지 않는지 응답 지연 회귀 검사로 확인한다.
