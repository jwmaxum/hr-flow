# 3-5 사용성 검증과 개선

측정 회사는 사용자가 지정한 **에스지앤플래닛**이다. 실제 담당자는 개선 배포 후 측정한다. 구현 중에는 합성 데이터와 ERP 권한별 테스트 계정으로 동작을 검증하며, 이 시간을 사람의 업무 처리 시간이나 개선율로 보고하지 않는다.

## 확인한 문제와 수정

| 업무 | 재현·소스 확인 결과 | 개선 |
| --- | --- | --- |
| 입고·출고 | 긴 입력 양식 아래에 미리보기·오류가 나타나 결과를 놓칠 수 있었다. 오류 행으로 돌아가는 연결도 없었다. | 검증 결과·오류 요약에 키보드 포커스를 이동하고, 행별 오류에서 해당 품목으로 돌아간다. 입력 내용은 유지한다. |
| 출고 | 단가 방식과 총액 방식을 전환하면 양쪽 입력 금액을 삭제했다. | 같은 품목 행 안에서 두 초안을 보관한다. 현재 선택한 방식의 값만 서버에 전송하고 변경 시 이전 미리보기를 무효화한다. |
| 미수금 회수 | 자동배분의 `Number` 변환은 `1,100`을 무시하고 `1e3`을 1,000으로 처리했다. `0.001 USD`는 반올림했지만 서버는 거절했다. | 서버와 같은 쉼표·소수 정밀도·허용 범위로 검증한다. 잘못된 값은 안내하며 조용히 무시하거나 반올림하지 않는다. |
| 미수금 회수 | 배분 합계·초과액을 서버 미리보기 전에는 확인하기 어려웠다. | 입력 중 선택 수금액·배분 합계·남는 수금·초과액을 표시한다. 확정 계산은 기존 서버 검증을 유지한다. |
| 미수금 회수 | 원장 반영일만 바꾸면 화면의 후보 문서·잔액은 이전 조회일 기준이었다. | 반영일별로 다시 조회한다. 응답 순서가 바뀌면 이전 응답을 무시하고, 조회 완료 전 자동배분·미리보기를 제한한다. 조회 실패 시 입력값을 보존한 재시도를 제공한다. |
| 미수금 회수 | 거래처 변경 시 이전 거래처의 입금액·참조번호·메모가 남았다. | 거래처·통화 변경 시 해당 입금 입력과 배분을 비우고 그 이유를 안내한다. |
| 미수금 회수 | 수금 확정 후 부모 목록 조회 실패가 같은 오류 경로로 처리됐다. | 확정 성공을 보존하고 목록 조회 실패를 별도로 안내한다. 재조회는 원수금이나 배분을 다시 생성하지 않는다. |

오류 위치는 필드 종류와 1~50의 행 번호만 전달한다. 제출 금액·메모·참조번호를 오류 메타데이터에 포함하지 않는다. 권한 검증 오류를 입력 오류로 바꾸지 않는다. 회사 분리, 입고/출고 담당 범위, ADMIN 수금 권한, 승인·변경 이력, 월마감 잠금, 확정 시 재검증과 중복 방지는 그대로 유지한다.

## 자동 검증과 실제 측정의 구분

격리 검사 시나리오는 INBOUND 담당자의 입고 오류 수정·확정, OUTBOUND 담당자의 단가/총액 전환·오류 수정·확정, ADMIN의 새 입금·부분배분·기존 수금 재사용이다. 별도 회사의 재고 불변, 잘못된 입력의 확정 차단, 수금 확정 후 조회 장애 복구도 검사한다.

자동화 결과의 `erp-usability-*.json`은 `AUTOMATED_NOT_HUMAN`으로 표시한다. 기록한 시간은 브라우저 자동화·의도적 오류 주입·결과 확인을 포함한 실행 시간이다. 실제 사용자 수는 0이며 사람의 완료시간 중앙값, 오류율, 개선율을 뜻하지 않는다. 운영 직원 이름, 이메일, 입력 내용이나 거래처 자료를 수집하는 기능은 추가하지 않는다.

현재 실제 담당자 측정 결과는 **미측정**이다. 개선 전 동일 조건의 사람 측정 자료가 없으므로 “처리 시간이 몇 % 줄었다”는 결론을 내리지 않는다. 이번 첫 실측은 후속 개선의 기준 자료로 사용하고, 이전 자료가 있는 경우에만 같은 조건의 결과를 비교한다.

### 배포 전 검증 결과

| 검사 | 결과 |
| --- | --- |

| 입출고·오류 복구·수금 통합 브라우저 회귀 | PC·모바일 6건 통과. 최초 실행에서 보조 설명이 입력란 이름에 합쳐진 문제를 찾아 이름과 설명을 분리한 후 재검증했다. |
| 비밀값·변경 범위 검사 | 변경 파일의 비밀값 노출 없음, 권한·회사 분리·승인 정책 변경 없음 |

운영 배포 범위는 Cloudflare Pages 웹과 `manageErpImport`, `manageErpFinance` 두 함수다. 별도 Firebase Hosting 배포나 운영 회사의 테스트 거래 생성은 하지 않는다. 전체 회귀와 같은 커밋의 운영 웹 배포 결과는 GitHub Actions와 Cloudflare 체크에서 확인한다.

## 에스지앤플래닛 담당자 측정 순서

운영에서는 예정된 실제 업무를 수행하며 측정한다. 테스트만을 위한 가짜 입고·출고·수금을 운영 장부에 등록하지 않는다. 금액·거래처·참조번호·비밀번호를 결과표에 적을 필요는 없다.

1. 담당자가 본인 계정으로 ERP 시작 화면을 연다. 입고는 INBOUND/BOTH, 출고는 OUTBOUND/BOTH, 미수금 회수는 ADMIN 권한을 사용한다. 권한은 측정을 위해 임의로 변경하지 않는다.
2. 첫 연습이나 사용법 설명 시간은 별도로 기록한다. 실제 업무 시작 전에 과제와 완료 조건을 읽는다.
3. 시작 화면에서 해당 업무를 선택하는 순간부터 시간을 잰다. 확정 완료 안내와 결과를 확인할 때 종료한다. 중간 도움, 중단, 네트워크 장애도 기록한다.
4. 업무별로 가능하면 비슷한 난이도의 3건 이상을 기록한다. 실제로 수행하지 않은 건을 0초·오류 0건으로 채우지 않는다. 같은 거래를 반복 등록하지 않는다.
5. 오류는 의도하지 않은 잘못된 입력 횟수, 확정 전 수정 횟수, 잘못 확정한 건수로 구분한다. 시스템이 정상적으로 차단한 입력도 별도 기록한다. 오류 없이 끝났다면 실제로 관찰한 0건을 적는다.

| 업무 | 완료 확인 | 관찰할 불편 |
| --- | --- | --- |
| 입고 | 창고·거래처·품목·수량·원가를 확인하고 입고 확정 완료 및 재고 변동 확인 | 품목 찾기, 오류 행 복귀, 입력 재검토, 결과 확인 |
| 출고 | 실제 일반/세트 품목과 입금상태·VAT 구분을 확인하고 출고·매출·원가 반영 확인 | 단가/총액 전환, 세트 재고 확인, 오류 수정, 문서 연결 |
| 미수금 회수 | 회사가 은행 내역을 확인한 뒤 새 입금 또는 기등록 수금을 선택하고 배분·남은 미수 확인 | 기존 수금 찾기, 부분배분, 초과액 확인, 반영일 변경, 완료 후 조회 |

## 실제 측정 기록표
