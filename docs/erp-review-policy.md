# 회사별 장기 미확인 기준 설정

2026-11-21 추가. 기존 누적 미확인 점검함의 분류 기준을 회사별로 설정한다.

## 사용 방법

- 회사 ADMIN: ERP → 상단 변경 확인 → 누적 미확인 점검함 → 알림 기준 설정.
- 미설정 기본값은 장기 미확인 **14일 이상**, 우선 확인 **30일 이상**이다.
- 1~3650일 정수로 입력하며 우선 확인 기준은 장기 기준보다 커야 한다. 변경 사유는 3~500자다.
- 저장하면 과거 미확인 내역도 새 기준으로 분류한다. 우선 확인은 장기 미확인에 포함된다.
- 기본값으로 복원은 사유를 입력한 후 실행하며, 변경 이력을 지우지 않는다.
- 다른 ADMIN의 동시 변경 또는 응답 유실 시 현재 기준 다시 조회로 저장값을 확인한다. 재조회하면 작성 중인 입력을 저장값으로 바꾼다.
- ERP관리자는 점검함을 조회하지만 기준 설정과 ADMIN 확인 완료를 대신할 수 없다. 기존 ERP관리자의 업무·승인·월마감 권한은 유지한다.

## 저장과 권한

`companies/{companyId}/erpReviewState/policy`에 기준일, configured, revision, 마지막 변경자·시각을 저장한다. 정책 문서가 없을 때만 기본값을 사용하며 잘못된 저장 자료나 회사 불일치는 거절한다. 기존 `erpReviewState` 직접 접근 차단·회사 삭제 정리를 그대로 사용한다.

`manageErpControl`의 `reviewPolicyGet`, `reviewPolicySave`는 트랜잭션 안에서 실제 회사 ADMIN을 다시 확인한다. 저장 시 expected revision을 비교하고 정책·`erpAudit`·`erpChangeHistory`를 원자적으로 기록한다. 동일한 값 재저장은 새 이력을 만들지 않는다. 새 패키지·인덱스·이관은 없다.

정책 변경은 재고·거래·확인 기록·장부 revision·월마감 잠금을 수정하지 않는다. 정책 이력은 기준정보 분류이며 새 중요 변경 미확인 건수를 만들지 않는다. ADMIN 또는 ERP관리자는 관리자 관리 → 변경 이력이나 기간별 변경 이력에서 변경 전후를 조회한다.

## 조회·구버전 호환

- 신규 점검함은 `filter: ALL | AGED | URGENT`, 상단 알림·오늘 할 일은 `reviewPolicyVersion: 1`을 보낸다. 서버 응답의 policy 값으로 제목·필터·집계·행 분류를 표시한다.
- 기존 열린 웹의 명시적 `minDays: 0 | 7 | 30`과 버전 없는 누적 알림·오늘 할 일 요청은 7/30의 기존 의미를 유지한다. 배포 후 새로고침하면 회사별 기준을 적용한다.
- 정책 revision과 기준값을 커서에 포함한다. 페이지 이동 중 다른 ADMIN이 설정을 바꾸면 처음부터 조회하도록 안내한다.
- 같은 창에서 저장하면 상단 알림·오늘 할 일·점검함을 갱신한다. 다른 창은 기존 알림 갱신 주기 또는 점검함 새로고침으로 확인한다.
- 한국시간 처리일의 날짜 차이를 쓰며 지급기일 연체와 별개다.

## 검증과 배포 범위

서버 회귀는 14/30 KST 경계, 임의 기준, 복원, 잘못된 입력, 실제 ADMIN/ERP관리자/타회사 경계, 동시 저장, 기존 커서 만료, 원본 거래·확인 기록 보존, 구버전 의미 보존을 포함한다. 데스크톱·모바일은 입력 검증, 저장, 재접속 유지, 동시 수정 충돌, 복원, 권한별 버튼을 확인한다.

웹은 `jwmaxum/hr-flow` main → Cloudflare Pages `hr-flow-chj.pages.dev`, 백엔드는 `manageErpControl`만 배포한다. 기존 인덱스·보안 규칙은 변경하지 않는다. 운영 검증은 검증 전용 회사로 수행한 뒤 자료와 계정을 정리한다.

공식 근거: [Firestore 트랜잭션](https://firebase.google.com/docs/firestore/manage-data/transactions), [동시성·격리](https://firebase.google.com/docs/firestore/transaction-data-contention).
