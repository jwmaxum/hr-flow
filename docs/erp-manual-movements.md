# 직접 입고·출고 등록

품목 목록의 기본 버튼은 `입고등록`이다. 품목 코드를 선택하면 동일 코드·품목명·규격·단위를 채운 입고 화면을 연다. 품목명 선택은 재고현황 조회이고, `품목 정보만 등록`과 수정은 기준정보만 변경한다.

## 업무 흐름

1. 입고등록 또는 출고등록에서 날짜, 창고, 거래처, 품목별 수량·단가를 입력한다. 한 문서에 최대 50행이며 통화·환율·단가기준은 문서 공통이다. 과세는 10%, 영세·면세는 0%다. 다른 세율은 기존 Excel 양식을 이용한다.
2. 기존 품목은 코드를 재사용한다. 신규 품목은 입고 화면에서 명시적으로 선택하고 신규 등록 확인을 체크한다. 기존 품목의 기본 매입단가를 새 거래단가로 덮어쓰지 않는다.
3. 거래처를 선택하거나 신규 거래처 정보를 입력하고 저장 동의를 체크한다. 출고는 매출처 또는 매입·매출처를 사용한다. 신규 거래처는 확정 시 회사 기준정보로 함께 저장된다.
4. 검증·미리보기에서 오류, 품목·거래처 신규 생성, 공급가액·세액·합계, 전체 창고 재고 변동을 확인한 후 확정한다. 입력을 바꾸면 기존 미리보기와 확인 체크가 해제된다.
5. 출고 확정 결과에서 `이 출고로 거래명세표 작성`을 선택하면 거래처와 출고 행을 채운 초안이 열린다. 초안 저장과 발행은 별도 확인 단계다. 기존 회사 인감과 PDF 보관 정책을 그대로 사용하며 문서 발행이 재고를 다시 차감하지 않는다.
6. 확정 거래의 취소·반품은 기존 입출고 총괄·원장의 기능으로 처리한다. 직접 등록 이력은 Excel 업로드의 공통 등록 이력에서도 조회할 수 있으나 원본 Excel 다운로드는 제공하지 않는다.

## 가격과 재고 평가

- 기존 입고단가 이력은 모든 창고의 기초재고와 확정 입고를 최신순으로 조회한다. 원 통화·세금 포함 여부, 원화 원가단가, 취소·반품 상태를 구분한다. 기초재고를 금액 방식으로 이관했다면 원 입력단가는 공란이며 금액/수량으로 계산한 원가단가를 표시한다.
- 이번 신규단가는 입력값을 별도로 표시한다. 확정 전후 재고수량과 재고금액은 서버 검증 결과를 사용한다.
- 전체 재고금액은 모든 창고의 현재 장부금액 합계다. 평균 재고단가는 이 금액을 전체 잔여수량으로 나눈 값이다. 잔여수량이 0이면 평균단가는 표시하지 않는다.
- 출고원가는 기존 Excel 거래와 동일하게 출고 창고의 이동평균원가를 적용한다. 마지막 수량을 모두 출고하면 해당 창고 장부금액 전액을 차감한다.
- 매출액은 부가세를 제외한 공급가액이다. 세액·부가세 포함 합계·원화 환산 매출·출고원가·매출총이익을 구분한다. 외화 거래는 기존 정수 스케일과 반올림 규칙을 사용한다.
- 기존 기초재고 기준일 이후 날짜로만 거래할 수 있으며 마지막 확정 거래보다 과거로 소급할 수 없다. 빈 신규 회사의 첫 직접 입고에 한해 거래일 전날의 재고 0으로 시작할 수 있다. 서버가 현재고와 원장이 모두 없는지 검사하고 미리보기에 이 사실을 표시한다. 기존 재고가 있는 회사는 먼저 기초재고를 이관해야 한다.

## 구현과 운영

- `manageErpImport.manualPreview`가 엄격한 입력 검증 후 기존 MOVEMENTS 행 스키마와 재고 계획·확정 트랜잭션을 재사용한다. 파일 생성이나 Storage 업로드가 필요하지 않다.
- `erpImports`의 source.kind=MANUAL과 요청 해시로 직접 입력을 구분한다. 동일 요청 ID는 멱등 처리하고 같은 ID의 변경된 입력은 거절한다. 별도 ID의 같은 내용은 새 거래로 허용한다. 파일의 SHA 중복 방지는 XLSX에만 적용한다.
- 거래번호와 일자별 처리순서는 서버가 생성한다. 미리보기 지문은 키 순서에 무관한 해시로 계산한다. 확정 시 관리자·회사·세션, 기준정보, 현재고, 원장 순서와 지문을 다시 검증한다. 재고 부족·오래된 미리보기·권한 변경은 전체 확정을 거절하며 부분 저장하지 않는다.
- `manageErp.purchaseHistory`는 회사 관리자 전용이다. 최신 원장 50행씩 스캔하고 입고·기초만 반환한다. 다음 커서가 있으면 계속 조회할 수 있다. 가격과 평균단가는 일반 직원에게 반환하지 않는다.
- 신규 Firestore 복합 인덱스: erpMovements의 itemId ASC / date DESC / order DESC / rowNo DESC. 기존 필터·정렬 인덱스를 유지한다.
- 배포 대상: Firebase `manageErp`, `manageErpImport`, Firestore 인덱스와 GitHub main 연동 Cloudflare Pages. 다른 callable은 공유 모듈 변경의 영향 범위를 검토하여 배포한다. 과거 미확정 미리보기는 새 지문으로 재검증해야 할 수 있다. 확정된 과거 거래는 변경하지 않는다.

## 회귀 검증

Firestore 에뮬레이터 테스트는 원가·판매가 분리, 세금 포함 거래, 같은 요청 재시도, 동일 내용의 별도 입고, 신규 회사 초기화, 여러 창고 합계, 단가 이력 페이지·취소·반품 표시, 관리자 권한·타 회사·세션 차단, 재고 부족·동시 확정과 거래명세표 발행을 검증한다. 브라우저 테스트는 데스크톱·모바일에서 코드 선택 → 입고 확정 → 출고 확정 → 거래명세표 초안을 확인한다. 운영 회사의 실제 입출고는 배포 검증 목적으로 생성하지 않는다.

다음 단계는 발주·입고 예정과 수주·출고 예정의 분리, 거래처별 미수금·수금 관리를 연결하는 것이다.

## 출고 품목 부분 문자열 검색

출고등록의 **등록 품목 선택**에서 품목코드·모델번호·품목명·규격의 일부를 입력한다. 모델번호는 기존 코드·품목명·규격에 저장된 내용을 검색하며 별도 모델번호 필드를 새로 요구하지 않는다. 대소문자와 전각/반각을 정규화하고, 공백으로 나눈 단어를 모두 포함하는 사용 중 품목을 찾는다. 검색 결과에는 코드·이름·규격·단위·세트 여부를 표시한다.

처음 불러온 50개에 한정하지 않고 로그인한 회사의 전체 품목을 확인한다. 서버는 한 요청에 최대 250개를 확인하고 최대 50개 일치 품목을 반환한다. 화면은 최대 2,000개까지 이어서 확인해 결과를 모으며, 남은 자료가 있으면 **검색 결과 더 보기 / 남은 품목 계속 검색**을 제공한다. 확인하지 않은 자료가 남으면 전체 검색 결과가 없다고 표시하지 않는다. 추가 인덱스나 기존 품목 이관은 필요하지 않다.

방향키·Enter로 선택하고 Escape로 목록을 닫는다. 검색어 변경 시 이전 선택을 해제하여 다른 품목이 의도치 않게 출고되는 일을 막는다. 한글 조합 입력과 지연 응답을 구분하며, 이전 검색이나 이전 회사의 응답은 반영하지 않는다. 입력만 하고 목록에서 선택하지 않은 값은 출고 확정에 사용하지 않는다. 입고의 신규 품목 입력과 기존 선택 기능은 유지한다.

키보드 조작과 선택 상태는 [WAI 콤보박스 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)을 기준으로 검증한다.
