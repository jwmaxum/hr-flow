# 로그인·첨부파일 브라우저 자동 점검

실제 React 화면에서 테스트 계정으로 로그인하고, 지출결의에 PNG·PDF를 첨부한 뒤 원본을 다운로드하는 절차를 자동 점검합니다. Firebase Authentication·Firestore·Storage·Functions Emulator를 함께 실행하며, 운영 로그인이나 운영 자료를 사용하지 않습니다.

## 실행 환경

- Node.js `24`, npm
- Java `21`과 실행 가능한 `java` 명령: Firestore·Storage Emulator에 필요합니다.
- Playwright Chromium
- 아래 로컬 포트를 사용할 수 있는 환경

| 서비스 | 고정 주소 |
| --- | --- |
| 테스트 웹 | `http://127.0.0.1:5173` |
| Authentication | `127.0.0.1:9099` |
| Firestore | `127.0.0.1:8080` |
| Storage | `127.0.0.1:9199` |
| Functions | `127.0.0.1:5001` |
| Emulator Hub | `127.0.0.1:4400` |

저장소 루트에서 다음 명령을 실행합니다. 초기 의존성·브라우저·Emulator 다운로드에는 인터넷 연결이 필요합니다.

```sh
npm ci
npm --prefix client ci
npm --prefix functions ci
npx playwright install chromium
npm run test:e2e:safety
npm run test:e2e
```

Linux의 새 실행 환경에서는 Chromium 시스템 라이브러리도 필요할 수 있습니다. CI는 브라우저와 해당 라이브러리를 설치한 뒤 점검합니다.

`test:e2e:safety`는 프로젝트·주소·자격 증명 차단 로직을 확인하는 Node.js 테스트로, 브라우저나 Emulator를 시작하지 않습니다. `test:e2e`는 필요한 Emulator와 테스트 전용 Vite 서버를 시작하고, 점검 종료 후 서버를 종료합니다. Playwright를 직접 실행하면 필수 격리 환경이 없어 실패하도록 구성되어 있으므로 위 명령을 사용합니다.

브라우저 실행에 앞서 기존 Firestore·Storage 규칙 회귀 검사도 같은 로컬 Emulator에서 실행합니다. 이 규칙 검사만 별도 합성 프로젝트 `demo-hr-flow`를 사용하며, 브라우저 계정과 데이터는 `demo-hr-flow-e2e`에 격리됩니다. 운영 빌드 후 `npm run test:e2e:boundary`로 테스트 설정이 배포 파일에 포함되지 않았는지도 확인합니다.

## 점검하는 업무

Chromium 데스크톱 `1440×1000`과 모바일 `390×844`에서 같은 업무를 실행합니다.

1. 플랫폼 운영자 `SYSTEM_ADMIN`, 회사 최초 관리자 `SUPER_ADMIN`, 일반 직원 `MEMBER`의 실제 로그인 폼과 역할별 화면 이동을 확인합니다. 일반 직원에게 플랫폼·조직관리 메뉴가 노출되지 않는지도 확인합니다.
   공개 랜딩의 SUIT 테마, 설명서 탭의 키보드 이동·목차 포커스·로그인 이동과 플랫폼 화면의 공통 셸·모바일 메뉴도 검증합니다.
2. 직원이 지출결의 화면에서 PNG와 PDF를 각각 선택하여 제출합니다. 실제 업로드 함수가 저장한 Firestore 첨부 경로·파일명·Storage 바이트를 확인합니다.
3. 지출결의 상세 화면의 다운로드 버튼을 사용하여 원래 파일명과 파일 바이트가 유지되는지 확인합니다.
4. 다른 회사의 문서 ID·회사 ID·파일 경로를 전달해도 타사 첨부파일을 읽거나 타사 데이터를 생성할 수 없는지 확인합니다. Firestore 규칙과 첨부 HTTP 함수 양쪽에 실제 인증 요청을 보냅니다.
5. 같은 본부의 `SUB_ADMIN`이 허용된 첨부파일을 읽을 수 있고, 다른 본부의 `SUB_ADMIN`은 읽을 수 없는지 확인합니다.
6. 정지·퇴사·Auth 비활성 계정의 로그인 또는 자료 접근 차단과, 로그인 후 세션이 취소된 계정의 첨부 접근 차단을 확인합니다.

외부 HTTP·WebSocket 연결은 테스트 브라우저에서 차단합니다. 첨부 API는 정확한 테스트 프로젝트의 두 첨부 엔드포인트에 한해 로컬 Functions Emulator로 연결됩니다. 운영 함수의 인증·회사·본부 검증과 Firestore·Storage 규칙을 그대로 사용합니다.

이 점검은 로그인·지출결의 첨부 경로의 회귀 검증입니다. 모든 HR 메뉴나 모든 브라우저의 정상 동작을 보증하는 전체 업무 테스트는 아니며, 기존 단위·보안 회귀·규칙 테스트와 함께 사용합니다.

## 테스트 자료와 운영 차단

각 실행은 서로 다른 회사 ID를 가진 합성 회사 두 곳과 테스트 조직도를 만듭니다. 플랫폼 운영자, 회사 관리자, 두 회사 직원, 같은·다른 본부의 결재자, 정지·퇴사·비활성 계정을 생성합니다. 이메일은 `example.invalid` 하위 주소만 사용하며 계정별 무작위 비밀번호와 인증 토큰은 실행 중 메모리에만 둡니다.

허용 프로젝트는 정확히 `demo-hr-flow-e2e` 하나입니다. Admin SDK를 가져오거나 초기화하기 전에 프로젝트 ID와 모든 Emulator 주소를 검증합니다. 운영 프로젝트, 다른 프로젝트, 외부 호스트, 다른 포트·URL 경로·사용자 정보가 포함된 주소는 거부합니다. `FIREBASE_TOKEN`, `GOOGLE_APPLICATION_CREDENTIALS` 등 배포 자격 증명이 전달된 직접 실행도 차단합니다.

실행기는 상위 프로세스의 비밀 환경변수와 `VITE_*` 설정을 제외하고, 임시 CLI 설정 경로를 사용합니다. 루트·client의 `.env.local`을 테스트 설정으로 읽지 않습니다. Functions 디렉터리에 `.env`, `.env.*`(`.env.example` 제외), `.secret.local`, `.runtimeconfig.json`이 있으면 함수가 운영 설정을 읽지 않도록 시작을 중단합니다. 해당 파일을 삭제하거나 운영 설정을 바꾸는 대신, 비밀 파일이 없는 별도 체크아웃이나 CI에서 실행합니다.

운영 서비스 계정·운영 계정의 비밀번호·GitHub/Cloudflare 토큰은 준비할 필요가 없습니다. 테스트를 위해 운영 자격 증명을 복사하지 않습니다. Storage 함수가 사용하는 기존 버킷 이름도 고정된 로컬 Storage Emulator로 연결되며 운영 버킷으로 전송되지 않습니다.

종료 시 해당 실행이 만든 회사 ID의 문서와 첨부 경로, 정확한 테스트 사용자 ID만 정리하고 Admin SDK 연결을 닫습니다. 프로젝트 전체 삭제나 운영 초기화 API는 사용하지 않습니다. 실행이 강제 종료되어 남은 자료도 일회성 로컬 Emulator에만 존재합니다.

## 결과 확인과 CI

결과는 Git에서 제외된 `test-results/e2e/` 아래에 저장합니다.

- 정리된 JSON 결과: 테스트 이름·성공 여부·소요 시간 등 실행 결과
- 실패 화면: 합성 계정 화면의 PNG 스크린샷

비밀번호·토큰·요청 본문을 결과에 남기지 않습니다. Playwright trace·영상·HTML/blob 리포트·로그인 상태 파일은 저장하지 않습니다. 실패 분석은 JSON의 실패 항목과 스크린샷, 비밀값을 생략한 실행 메시지부터 확인합니다.

GitHub Actions의 검증은 `main` push, `main` 대상 pull request, 수동 실행에서 동작하며 배포 권한이나 운영 비밀값 없이 이 점검을 실행합니다. Cloudflare Pages의 Git 연동 빌드는 별도로 실행되므로, 검증 워크플로 성공이 Cloudflare 자동 배포의 선행 조건으로 연결되어 있지는 않습니다. 다음 운영 단계로 E2E를 필수 체크로 지정한 브랜치 보호와 배포 승인 연계를 권장합니다.

자동 점검은 운영 계정·자료를 사용하지 않습니다. 이번 검사에서 발견된 첨부 경로 위조를 막기 위해 공유 Firestore 보안규칙의 저장 검증을 강화합니다. 정상 첨부 및 변경하지 않은 기존 첨부 참조는 유지하며, 지출결의의 월말 날짜에서 월 목록이 중복되던 계산도 보완합니다. 웹 배포 대상은 `jwmaxum/hr-flow`에 연결된 새 주소 [hr-flow-chj.pages.dev](https://hr-flow-chj.pages.dev/)입니다. 기존 [hr-flow.pages.dev](https://hr-flow.pages.dev/)의 웹 파일은 이번 배포 대상에서 제외하고 이전 배포 버전을 그대로 유지합니다.

고정한 개발용 Firebase CLI 의존성에는 중간 등급 감사 경고 5건(원인 취약점 2종, 높음·치명적 0건)이 남아 있습니다. 현재 호출되는 코드는 해당 취약 API를 사용하지 않으며 운영 웹 번들에도 포함되지 않습니다. CLI 하향 또는 하위 라이브러리의 강제 메이저 변경 대신, 호환되는 상위 수정 버전이 나오면 재검증 후 갱신합니다.
