# 재고 상태와 창고별 세트 표시

3-3 단계는 `품목·재고 → 품목·재고현황`, 세트 등록·출고의 구성품 미리보기, 보관·차용 화면의 용어를 통일한다. 원장을 새로 이관하거나 운영 수량·원가를 자동 수정하지 않는다.

| 상태 | 표시 기준 | 재고자산·세트 출고 가능 수량 포함 |
| --- | --- | --- |
| 회사 소유 재고 | `erpInventory`의 확정 수량과 장부금액 | 포함. 세트는 활성 품목·창고의 회사 소유 구성품만 사용 |
| 고객 소유 보관품 | `erpCustodyLots.availableQuantityScaled`, 실제 창고에 보관 중인 고객 소유 수량 | 제외 |
| 차용 미반환 | `erpBorrowings.outstandingQuantityScaled`, 다른 거래처에 빌려 판매한 뒤 반환할 의무가 남은 수량 | 제외. 실제 보관 중인 수량으로 다시 더하지 않음 |
| 원가 미확정 대기 | 품목의 `pendingOpening` 원본 수량·단위·기준일 | 제외. 원가 입력·기초재고 확정에서 별도 확정 |

차용 미반환은 반환 의무를 뜻하는 **양수 수량**으로 표시한다. 보관 원장의 차용 수량과 차용 원장의 미반환 합계를 대사하며, 불일치하면 조회 오류로 알린다. 두 원장의 차용 수량을 중복 합산하거나 음수 회사 재고를 자동으로 차용 내역으로 바꾸지 않는다. 인도 완료와 취소된 보관품은 실제 보관 수량에 더하지 않는다.

회사 소유 재고가 아직 없으면 `미등록`, 확정된 0개는 `0`, 원본 수량이 공란이면 `수량 미입력`, 원가 미확정 대기 자체가 없으면 `없음`을 표시한다. 확인한 0원 원가와 원가 산정 불가는 다르게 표시한다. 확정 회사 재고와 대기 수량이 동시에 존재해도 각각 표시하며 대기 수량을 더하지 않는다.

대기 수량은 원본의 품목 전체 수량이며 **창고 미지정**으로 표시한다. 세트의 여러 창고 구성품 상세에 같은 원본 대기가 표시되어도 창고별로 배정된 수량이 아니다. 보관·차용 원장이 있는 창고에 회사 소유 재고가 없으면 회사 소유 항목은 미등록으로 표시한다. 사용 중지 창고의 보유 자산·보관·반환 의무는 보존하여 보여준다.

## 창고별 세트 수량과 원가

세트의 별도 재고자산을 생성하지 않는다. 창고별 출고 가능 수량은 각 구성품의 `회사 소유 수량 ÷ 세트당 구성수량`을 내림한 값 중 최솟값이다. 화면 합계는 각 활성 창고에서 완성할 수 있는 세트 수량의 합이다. 서로 다른 창고의 부족 구성품을 합쳐 출고 가능한 것처럼 표시하지 않는다. 사용 중지 창고·세트·구성품은 출고 가능 수량이 0이며 이유를 표시한다.

예를 들어 A 2개와 B 1개로 구성하는 세트에서 본사에 A 4개/B 1개, 연구소에 A 1개/B 4개가 있으면 본사 1세트, 연구소 0세트, 합계 1세트다. 창고 이동으로 수량을 실제 배분한 후 다시 조회한다.

품목 화면은 창고별 **1세트 예상 원가**와 구성품별 수량·원가를 표시한다. 요청 수량의 예상 원가는 세트 등록·출고 미리보기에서 확인한다. 같은 계산 함수를 사용하며 구성품마다 요청 수량에 해당하는 이동평균원가를 원 단위로 반올림한 뒤 더한다. 반올림한 1세트 원가에 요청 세트 수량을 단순 곱하지 않는다. 구성품이 부족하면 예상 원가를 산정 불가로 표시한다. 마지막 수량을 모두 출고할 때는 남은 장부금액을 사용한다.

출고 가능 수량 표시는 완전한 1세트 기준이다. 기존 소수 세트 출고는 요청 수량과 구성수량의 곱이 소수점 4자리 범위에 들어오는지 별도로 검증한다. 여러 출고 행에서 공유하는 구성품은 기존 출고 검증·확정에서 합산하고, 확정 시 최신 수량·원가를 다시 읽는다. 조회 수량을 예약하거나 예상 원가를 확정 원가로 저장하지 않는다.

## 권한·대사·검증

- 회사 경로와 현재 직원의 ERP 권한을 트랜잭션 안에서 재검사한다. 재고 조회에 추가하는 보관·차용 정보는 수량 합계이며 고객명, 소유 거래처 ID, 원판매 증빙, 비고, 차용 평가금액은 반환하지 않는다. 상세 보관·차용 관리는 기존 ADMIN 영역에서 처리한다.
- 품목 화면의 금액·창고별 예상 원가는 기존 품목 화면과 같은 ADMIN·ERP관리자 표시 범위를 사용한다. 세트 등록·출고에서 허용하던 담당자의 단가·예상 원가 조회 체계와 기존 서버 권한은 유지한다. 새 조회로 금융·승인·월마감 권한을 부여하지 않는다.
- 음수·소수점 범위 오류, 중복 창고 재고, 0개인데 남은 금액, 다른 회사 자료, 누락 창고, 손상된 세트 구성, 보관·차용 불일치는 부분 합계를 제공하지 않고 오류로 처리한다.
- 한 회사 최대 500개 창고, 품목별 재고/보관/차용 각각 500개, 한 조회 최대 10,000개 원본 행을 검증한다. 한도를 넘으면 생략한 합계 대신 명시적인 오류를 반환한다. 새 패키지·컬렉션·인덱스·규칙 변경은 없다.
- 회귀 검사는 소유권별 분리, 0/미등록/공란/0원 원가, 비활성 창고·품목, 창고 간 미합산, 소수 및 반올림, 오염 자료·회사 격리·권한 회수, 실제 보관·차용·현물 반환·세트 출고 대사를 포함한다. PC·모바일에서 상태 카드, 창고별 세트 상세와 기존 기초재고 확정·출고 흐름을 확인한다.
